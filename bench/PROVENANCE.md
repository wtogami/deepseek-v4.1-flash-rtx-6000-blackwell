# Benchmark script provenance

`llm_decode_bench.py` is the **exact script** that produced the Karmic Kraken
measurement table in `rtx6kpro/benchmarks/karmic-kraken-serving.md`.

- Source: <https://github.com/local-inference-lab/llm-inference-bench>
- Commit: `ccd9ad8ced7e387794391bfb0ac6d99b1f66ba6f` (2026-09-06, "Release v0.6.2
  with guarded decode metrics and output preview")
- sha256: `053989edff8c9c93e2b96e61342b2ffbd9851e03deba17e6d3fc96fcd6694c1e`
- This sha256 is byte-identical to `bench_sha256` recorded in
  `rtx6kpro/benchmarks/karmic-kraken-serving-samples.json` (ds41.kk), which is
  how the commit was identified: every historical revision of the file was
  hashed until the match was found.

The KK invocation recorded in the samples JSON (per cell, five 30 s windows):

```
llm_decode_bench.py --host http://<host>:<port> --model DeepSeek-V4.1-Flash \
  --display-mode plain --no-hw-monitor --no-resume --respect-eos \
  --temperature 1 --token-targeting exact --max-tokens 8192 \
  --decode-warmup-seconds 15 --kv-budget <logical_kv_capacity_tokens> \
  --prefill-only --prefill-contexts 32k --prefill-duration 30 \
  --prefill-metric client --output prefill-N.json
```

```
llm_decode_bench.py ... (same global flags) \
  --skip-prefill --concurrency 1,8 --contexts 0 --duration 30 \
  --output decode-N.json
```

`run-bench.sh` reproduces exactly these invocations against the local server.
`--kv-budget` is the server's logical KV capacity from its startup log
("GPU KV cache size"); it only gates over-capacity cells, which the 32K
prefill and context-zero decode cells never are.

Runtime dependencies (host python3, versions recorded at audit time):
httpx 0.28.1, rich 14.3.2, psutil 7.2.2. The script itself is the methodology;
library versions only affect transport and rendering.

Do not edit this file. A different hash means a different methodology.
